ES 335 · FROM FIRST MODEL TO REVISED PIPELINE

From a small crop
to an object class.

This project asked whether simple visual clues could identify five everyday objects in images from a robotic-manipulation dataset. Each labelled object crop was converted into numeric descriptions of its edges and colors. Three machine-learning models were compared, and their errors were examined.

How this project evolved. The first pipeline was checked on a small set of real photographs of everyday objects outside the VMRD dataset. Those informal checks showed that small changes to image size could change a prediction. This prompted a closer look at the design, revisions to the pipeline, and a comparison of both versions on a separate held-out test set. This page follows that story.

THE QUESTION

What did the model predict?

The task was to predict which of five named categories appeared in one crop containing one object.

The five target categories were apple, cans, cup, stapler, and toothpaste. The model received pixels from a crop and returned one class label. It could also return scores for all five labels, so the page could show whether its first choice was clear or close to a second choice.

Each sample was a rectangular crop around one object, not a complete photograph of a busy table. Each object was cut out using the bounding-box coordinates in the dataset’s XML annotations. The classifier therefore saw one object at a time, not a full scene.

Scope boundaryA sorting robot needs to know what an object is before deciding where to send it or how to handle it. This project isolated only that identification step: it answered “What is this cropped object?” It did not locate objects in a scene, calculate a safe grasp pose, or assess physical feasibility.

02

THE DATA

From crowded scenes to single objects

The source data described manipulation scenes; the working table described individual object instances.

VMRD is the Visual Manipulation Relationship Dataset. Its photographs showed objects in real, sometimes cluttered arrangements. Each matching XML file recorded the objects in the scene. The object’s name field supplied its label, and its bndbox coordinates defined the crop rectangle.

Five categories with reasonably similar counts and visually distinct kinds of objects were selected. The index, father, and children fields were intentionally excluded. Those fields encoded an object-order relationship for manipulation: which objects were above or depended on others. That was useful for deciding what a robot should move first, but it was not needed to answer the class-identity question. The separate Grasps/ folder described grasp rectangles, which this classifier also did not use.

Filtering kept a scene if it contained at least one of the five selected classes. Cropping then created one separate image for each target object. A scene with three target objects could therefore contribute three rows.

WHAT ONE ROW MEANS

One object, one label

Each row represented one object image. It held 8,100 numbers describing the edge patterns in that crop, 512 numbers describing its color distribution, and one label — the object's class name. That numeric row was what the model trained on; the original pixel image was not used after this point.

DATA QUALITY TO REMEMBER

Real packaging carried extra visual clues

Some crops contained printed logos and words. Those edges were part of the pixels the model saw. A shape descriptor could respond to the writing as well as the object's outline, so high scores did not prove the model had learned only the intended shape.

03

FEATURES · HOW PIXELS BECAME NUMBERS

How pixels became a compact description

Each crop was converted into a numeric description: 8,100 values summarized local edge directions and 512 values summarized color distribution. In v2, the descriptions stayed in separate streams until their class scores were combined.

A
STEP 1 · STANDARDIZED IMAGE SIZE

Every crop used a fixed 128 × 128 frame

Crops naturally had different widths and heights, but HOG needed every image to have the same dimensions so its feature values lined up. The pipeline preserved the object's proportions: it padded the shorter dimension by extending its edge pixels, then resized the square uniformly to 128 × 128. This filling step is called letterboxing. It avoided squashing tall or wide objects just to fit the model's fixed input.

What is a pixel, and what does resizing change?

A pixel is one small square of color or brightness in a digital image. Resizing samples or combines pixels to fit a requested size. Letterboxing first adds pixels around the shorter side, so the object itself keeps its proportions when the image is resized.

STEP 2 · KEPT TWO VIEWS

Two image views retained color and edge information

Two types of evidence were retained. Color could help separate an apple from a neutral-colored stapler. Edge direction and shape could help distinguish a cup from toothpaste packaging. The grayscale image retained brightness but removed hue and saturation. The color image was kept separately so those details remained available to the color feature.

Why not feed color into every calculation?

Histogram of Oriented Gradients summarized brightness changes across neighboring pixels without using color channels. Color was summarized separately with an HSV histogram.

STEP 3 · NORMALIZED LOCAL CONTRAST

CLAHE strengthened local contrast before edge extraction

CLAHE stands for Contrast-Limited Adaptive Histogram Equalization. In simple terms, it adjusted brightness contrast separately in small neighboring regions rather than applying one adjustment to the whole crop. This could make faint edges easier to see when lighting varied across an object. “Contrast-limited” meant it capped the adjustment so a small dark region was not amplified without bound. This run used OpenCV CLAHE with clipLimit 2.0 and an 8 by 8 tile grid.

What is contrast?

Contrast is the difference in brightness between neighboring parts of an image. A dark outline next to a bright background has strong contrast; two similar shades have weak contrast. HOG relies on these changes.

STEP 4 · HOG · EDGE DESCRIPTION

HOG measured edge direction and strength

Histogram of Oriented Gradients (HOG) summarized edge directions. In a small patch, a rapid brightness change marked an edge. HOG measured the direction of those changes—horizontal, diagonal, or vertical—and recorded their strength. It repeated this across many small regions and joined the measurements into one long list.

The result was not a list of object parts, and HOG did not understand the word “cup.” It was a numeric pattern of local edges. A model later learned that certain patterns often occurred in crops labelled cup, cans, or another class.

Move the direction slider. The edge stays fixed while the arrow rotates. Brightness change is strongest when the arrow crosses the edge and weakest when it runs along the edge.

How did nine directions, 8-pixel cells, and 2 × 2-cell blocks produce 8,100 numbers?

The resized image was 128 pixels wide and high. Dividing it into 8-pixel cells produced a 16 by 16 grid. Each HOG block covered 2 by 2 neighboring cells; sliding that block one cell at a time produced 15 by 15 block locations. For each of the four cells in a block, HOG recorded nine direction-bin values. The resulting size was 15 × 15 × 2 × 2 × 9 = 8,100 values. The blocks overlapped, which let the description capture nearby edge context.

L2-Hys was the normalization used for each block. It rescaled the values so a block's description was less sensitive to overall brightness or contrast, then limited unusually large values before normalizing again.

STEP 5 · HSV · COLOR DESCRIPTION

HSV summarized color in 512 bins

The color image was converted from BGR (the channel order used by OpenCV) to HSV. Hue represented the color family, Saturation represented how vivid or grayish it was, and Value represented brightness. Each channel was divided into eight ranges, and every H–S–V combination was counted, producing 8 × 8 × 8 = 512 bins. The histogram was then L2-normalized: the vector was divided by its Euclidean length (the square root of the sum of its squared bin values), making its overall magnitude comparable across crops.

The histogram recorded how much of each color combination appeared, but not where those colors appeared in the image. The HOG stream contributed local edge layout; the HSV stream contributed an overall color summary.

Why HSV rather than RGB?

In RGB, brightness and color are mixed across red, green, and blue values. HSV allowed the histogram to count Hue, Saturation, and Value separately. This representation did not make the features immune to lighting changes.

04

BASELINE AND MODEL CHOICES

How the three model families differed

Three model families were compared because they learned different kinds of rules from visual feature values.

Logistic Regression was the linear baseline. An RBF Support Vector Machine could represent curved boundaries, while a Random Forest combined many decision trees. In pipeline v1, each model family learned from the combined 8,612-value vector. In v2, each family had one classifier for HOG and a second for color; their probabilities were blended after prediction.

A baseline is a reasonable first method used as a reference for later changes. The same model families were kept across versions so the comparison could focus on revised image preparation, feature handling, and tuning. V2 searched model settings and the HOG/color fusion weight using five-fold validation inside the training pool.

A MODEL LEARNS A RULE

During training, each algorithm saw rows of numeric feature values paired with known labels. It adjusted internal values so its predictions better matched those labels. After fitting, the model could assign new feature values to the class whose learned rule fit best.

The model family stayed the same in v2; the change was that shape and color were learned in separate streams before their scores were combined.

01 · LINEAR

Logistic Regression

It combined feature values with learned weights and calculated a score for each class. The largest score determined the prediction. Despite “regression” in its name, This model was used for classification.

What does “linear” mean here?

For each class, the model adds weighted feature values. The boundary between classes is a flat dividing surface in the high-dimensional feature space. “Flat” does not mean the crop looks like a line; it describes the mathematical decision rule.

02 · KERNEL

Support Vector Machine · RBF

The SVM searched for a boundary that separated classes with a wide margin. The RBF kernel let that boundary bend based on similarity between examples, so it could capture more complex patterns than a flat boundary.

What is a kernel?

A kernel computes how similar two feature vectors are, without requiring the model to explicitly construct a new giant feature space. RBF means radial basis function: examples close together in feature space have more influence on each other than far-apart examples.

03 · ENSEMBLE

Random Forest

The forest trained many decision trees. Each tree asked a sequence of feature-value questions and reached a class at a leaf. The forest combined the trees' outputs. It provided a useful contrast to the smoother boundary of an RBF SVM.

What is a decision tree?

A tree is a chain of if/then splits, such as “is this feature above a threshold?” Each split narrows the possible classes until a leaf supplies a result. A random forest averages many trees rather than relying on one chain.

V2 PARAMETER SEARCH

What did the two-stream tuning select?

A hyperparameter is a setting chosen before fitting that controls a model. V2 tried candidate model settings together with three fusion weights: α=0.3, 0.5, or 0.7. Five-fold cross-validation compared the fused predictions using only the training pool. The HOG and color scalers were fitted separately inside each fold. The selected α was the share assigned to HOG; the remaining share went to color.

HOW V2 CLASS SCORES ARE MADE

Two probability lists are calibrated, then blended

For Logistic Regression and SVM, v2 used three-fold sigmoid calibration inside each HOG and color classifier. Calibration mapped model scores to probability-like class scores, making the two streams easier to blend. Random Forest supplied tree-vote probabilities directly. The final five class scores were the weighted average of the HOG and color scores. Calibration made the scores usable for this combination, but did not guarantee perfect real-world probability accuracy.

WHY THIS MATTERS

A threshold depends on the score

The rejection rule compares the top fused class score with a chosen threshold. A threshold is a policy for accepting or flagging a prediction; it does not change the model’s probability scores. A score is not a promise that a prediction is correct, and the same threshold can yield different coverage for each model.

05

EVALUATION DESIGN

How the final test set stayed unseen

The final test portion was set aside first. Tuning used only the remaining training pool, and test results were reported after all choices were fixed.

The evaluation used three levels: (1) the training pool fitted candidate models, (2) five-fold cross-validation estimated how candidate settings performed and selected hyperparameters, and (3) the separate held-out test set checked the selected model at the end. The test set contained 20% of the crops (838 examples); it was not used to choose settings and was evaluated once per model in the final evaluation script. Hyperparameter selection used five-fold stratified cross-validation on the training pool only. The held-out test set was not used for model selection or tuning; each finalized model was evaluated on it once. This separation helped prevent tuning decisions from inflating the reported test scores. The test score still estimated performance on similar crops from this dataset; it did not guarantee performance on new scenes.

The split used test_size=0.2, stratification, and random_state=42. The fixed random state made the same rows reproducible each run; stratification kept each class in roughly the same proportion in the training pool and test set. The remaining 80% (3,350 crops) was the training pool. In five-fold stratified cross-validation, it was divided into five parts: each round fitted on four parts and validated on the fifth, rotating until each part had served as validation. Grid search compared the candidate hyperparameters using these five validation results. After selection, the chosen model was refitted on all 3,350 training-pool crops, then evaluated on the untouched 838-crop test set.

WHAT CROSS-VALIDATION MEANS

Five validation rounds, one training pool

A validation fold is a temporary set of examples used to compare settings while the model is being developed. It is different from the final test set: the CV scores help choose hyperparameters, while the test score is reserved for the final report. “Stratified” means each fold keeps approximately the same mix of the five labels, so a round is not accidentally missing a class.

IMPLEMENTATION CAVEAT

V2 kept fold scaling separate

The original v1 tuning script fit StandardScaler on the full training pool before making CV folds, allowing each fold’s validation images to influence its scaling averages. In v2, the tuning code fitted each stream’s scaler using only that round’s four training folds, then applied it to that round’s validation fold. The final test set remained separate in both versions. The split was still crop-level, so results estimated performance on similar crops from this dataset rather than guaranteeing performance on entirely new scenes or environments.

ABSTAIN WHEN UNCERTAIN

Confidence threshold and accepted predictions

At each threshold, the system accepts an item only when its top class score meets or exceeds that value. Coverage is the fraction accepted; accuracy is calculated only for those accepted test crops. Raising the threshold usually means fewer predictions are accepted. It does not improve the underlying model or change its probabilities.

DEBUGGING STORY · FROM V1 TO V2

Why the first pipeline was revised

The first pipeline was tried on a small set of real photographs of everyday objects outside VMRD, including apples, toothpaste tubes, and staplers. These informal checks helped identify questions to investigate; they were not a formal evaluation.

What the checks showed. In these informal checks, some predictions were wrong despite receiving high scores. Slightly changing an image’s size would change its predicted label, and staplers seemed especially difficult in this small set. These observations suggested questions to investigate; they could not estimate how often the model would fail in general. This real-photo observation was separate from the held-out VMRD results: in v1, held-out stapler recall was 92.13% for Logistic Regression, 88.98% for SVM, and 76.38% for Random Forest.

Two design questions. First, v1 used cv2.resize to force each rectangular bounding-box crop directly into 128 × 128 pixels. That could squash a tall toothpaste tube or widen a flat object; HOG then described the distorted proportions. Second, v1 joined 8,100 HOG edge values and 512 HSV color bins into one 8,612-value vector. Although StandardScaler normalized each column, a feature group with many more columns could contribute many more terms to distance calculations. HOG outnumbered color about 15 to 1, which created a risk that color would have too little influence; this did not mean the model literally ignored color or prove that it caused each error.

Scaling detail. The original tuning code also fitted one StandardScaler on the full training pool before cross-validation, so validation-fold images influenced those scaling averages. V2 fitted separate HOG and color scalers inside each CV training fold. The held-out test set stayed out of scaler fitting in both versions.

V2 CHANGE 1 · PRESERVED SHAPE

How v2 preserved object shape

V2 added replicated edge pixels to the shorter side until the crop was square, then resized the square uniformly to 128 × 128. “Letterbox” means filling the unused space around an image so the whole object fits a fixed frame without stretching it. Replicating edge pixels avoided drawing a new, sharp, flat border that could look like an artificial edge to HOG.

V2 CHANGE 2 · KEPT STREAMS SEPARATE

How v2 combined model scores

V2 trained one HOG classifier and one color-histogram classifier for each model family. Each stream had its own StandardScaler. A classifier’s probability scores were then combined: alpha × HOG probability + (1 − alpha) × color probability. Cross-validation tuned alpha and the model settings together. All three selected alphas were 0.5, so each stream contributed half of the combined score.

LIMITS AND NEXT QUESTIONS

What these results supported—and could not support

Good results on pre-cropped examples supported a narrow claim: these features could distinguish these five classes in this dataset.

They did not establish that a robot could find the objects in a new room, handle occlusion, or grasp safely. The experiment removed detection from the question by using reference bounding boxes; the live demo asks the visitor to make the crop for the same reason.

A SMALL CHANGE TO DEFEND

Raising the confidence threshold would send more low-score cases for review. Coverage would fall, while accuracy among the accepted cases may rise. The exact trade-off had to be read from the saved held-out threshold data; it could not be inferred from one test accuracy.

DATA SCOPE

Five classes from one dataset

The results applied to apple, cans, cup, stapler and toothpaste crops prepared from VMRD. The class counts were fairly close, between 636 and 916, but a real sorting system could see very different class frequencies. The study did not test other object categories or that kind of imbalance.

TEST SPLIT

A held-out crop is not a new-scene test

The 20% test split was stratified by crop, not grouped by original photograph. Since one scene could produce several crops, crops from the same photograph may have appeared in both training and test sets. That overlap was not checked. Shared scene background, lighting or camera style could make test crops more familiar than genuinely new photographs.

FEATURE LIMIT

Edges and color do not understand objects

HOG records edge direction and strength; HSV records color counts. Neither knows what an object is. A printed logo, shadow or background boundary can look like a useful clue. A small crop, blur, unusual lighting, occlusion or a cut-off object can change those clues. Resizing to 128 × 128 also removes fine detail; letterboxing preserves shape but cannot restore missing pixels.

MODEL CAPACITY

The classifier only saw an edge-and-color summary

Before classification, each crop was reduced to two summaries: HOG recorded where brightness changed to form edges, and HSV counted color ranges. Logistic Regression, the RBF SVM and Random Forest learned which combinations of those numbers matched the five labels. If a useful clue was lost when the image became these summaries, the classifiers could not use it. A convolutional neural network (CNN) learns patterns directly from pixels, building from simple textures toward larger shapes. It could capture richer clues, but it would need many varied labelled images and its own careful testing; it would not guarantee better predictions. No CNN was trained in this project, so its performance could not be compared directly.

GENERALIZATION

High test accuracy does not promise outside performance

The 91–92% v2 accuracy described this particular held-out crop split from one dataset and one crop-making process. It did not prove that the model would work equally well on a random photo from another phone, room, angle or lighting condition; performance on an unrelated outside photo could be much worse, and this experiment did not measure how much worse. So 91–92% did not automatically mean the models were robust or very good on new photos. Training and test crops came from the same dataset and crop-making process, so they may have shared recurring visual conditions. The split was by crop rather than by original scene; crops from one photograph may therefore have appeared on both sides, making the test examples more familiar than genuinely new scenes. The models may have overfit to patterns specific to these data, which could make the test score overly optimistic. This evaluation could not measure that effect; a scene-grouped split and independent photographs were needed to estimate it.

DECISION SCOPE

A class score is not a safe grasp

The top score can be high even when the predicted class is wrong, especially when an uploaded crop differs from the training examples. The threshold only decides whether to show the identity result or flag it for review; it cannot repair a mistaken prediction. The “GRASP” badge was only an identity-confidence gate. The model did not locate objects in full scenes, estimate pose, check collisions, or predict whether a physical grasp would succeed.

CONCLUSION · KEY TAKEAWAYS

Useful evidence, with a clear boundary

This project showed that simple edge and color descriptions could classify many pre-cropped VMRD examples, while also showing why a good score on one dataset was not the same as dependable recognition everywhere.

Building the first pipeline made a preprocessing choice visible: forcing every rectangle into a square changed object proportions, and changing image size could change a prediction. V2 preserved proportions with letterboxing and kept shape and color in separate streams before combining their scores. On the same held-out split, v2 Random Forest improved over its v1 result, while the other model changes were smaller and did not all move in the same direction. Because preprocessing, feature handling and tuning changed together, the difference could not be attributed to one change alone.

The strongest conclusion was therefore specific: these three classical models learned useful patterns for five categories in the prepared VMRD crops. They did not learn a general concept of “can” or “stapler.” A visitor's crop could still be classified incorrectly if it showed a different product, a new background, poor lighting, an unusual view, motion blur, only part of an object, or several objects at once. Because both training and test examples came from VMRD and the same crop pipeline, they may have shared visual regularities that an unrelated photo would not. Small details could also disappear when the crop was reduced to 128 × 128 pixels, and a model could mistake text, shadows or background edges for object shape.

The reported accuracy came from a stratified random split of crops from the same dataset. Since multiple crops could come from one source scene and the split was not grouped by scene, some test examples may have shared scene conditions with training examples. That made the score useful for comparing these pipelines on this split, but insufficient to estimate performance on unrelated photographs. It did not, by itself, prove overfitting; a stronger next evaluation would hold out entire source scenes and test on independently collected images across cameras, rooms, lighting and object variants.

Finally, the models had a limited input: fixed HOG and HSV summaries, not a learned representation of the full image. A neural network could learn more complex visual patterns, but would require substantially more varied labelled data and its own held-out tests. Neither model family could be assumed correct without evidence. The next step would be to test on new scenes, inspect failure cases, measure confidence calibration, and only then decide whether a larger model was justified.
