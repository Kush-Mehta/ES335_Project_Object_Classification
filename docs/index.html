THE QUESTION

What exactly is being predicted?

For one crop containing one object, predict which of five named categories it belongs to.

The categories are apple, cans, cup, stapler, and toothpaste. The model receives pixels from a crop and returns one class label. It can also return scores for all five labels, so we can see whether its first choice was clear or close to a second choice.

A sample is not a complete photograph of a busy table. It is a rectangular region that has already been drawn around one object. The original dataset provides these rectangles in its XML annotations. During this experiment, those annotations stand in for an earlier object detector.

Scope boundaryA sorting robot may need object identity to choose a destination or handling routine. This project isolates only that identity step: it answers “What is this cropped object?” It does not answer “Where are all the objects in this scene?” and it does not calculate a safe robot grasp.

02

THE DATA

From crowded scenes to single objects

The source data describes manipulation scenes; our working table describes individual object instances.

VMRD is the Visual Manipulation Relationship Dataset. Its photographs show objects in real, sometimes cluttered arrangements. Each matching XML file records the objects in the scene. We read the object’s name as its label and its bndbox coordinates as the rectangle to crop.

The five categories were selected to have reasonably similar counts and visually distinct kinds of objects. We intentionally did not use the index, father, or children fields. Those fields encode an object-order relationship for manipulation: which objects are above or depend on others. That is useful for deciding what a robot should move first, but it is not needed to answer our class-identity question. The separate Grasps/ folder describes grasp rectangles, which this classifier also does not use.

Filtering keeps a scene if it contains at least one of the five selected classes. Cropping then creates one separate image for each target object. A scene with three target objects can therefore contribute three rows.

One object, one label

The manifest connects an image path to a class name. For example, a row might point to a crop saved under Crops/apple/ with label apple. It is not a row for the whole original scene.

DATA QUALITY TO REMEMBER

Real packaging carries extra visual clues

Some crops contain printed logos and words. Those edges are part of the pixels the model sees. A shape descriptor may respond to the writing as well as the object's outline, so high scores do not prove the model learned only the intended shape.

A useful file check is that the manifest, labels, and feature array have the same number of rows. The provided project outputs contain 4,188 rows, which also equals the sum of the five class counts. During a rebuild, check the feature script warnings for unreadable images.

Access and sharing. This repository keeps the text manifest, labels, code, and results. It omits the original images, generated crops, and the roughly 275 MB feature matrix. The dataset should be downloaded separately and placed in VMRD V2 fixed/; the numbered scripts rebuild the derived files. VMRD V2 archive · VMRN paper.

03

ORIGINAL FEATURES · PIPELINE V1

Pixels become a compact description

The first pipeline turned each crop into one 8,612-value list: 8,100 values describing local edge patterns plus 512 values describing color. The next chapter explains why we later changed how these features were prepared and combined.

A
STEP 1 · STANDARDIZE IMAGE SIZE

Resize each crop to 128 × 128 pixels

Crops naturally have different widths and heights. We resize each one to a fixed square so the next calculation always examines the same number of image locations. This is important because HOG produces a feature vector whose length depends on image dimensions. Fixed size makes the vectors line up column by column in the feature table. The training code crops the XML bounding box first, then directly resizes that crop to 128 × 128; a non-square training crop may therefore be stretched. The website uses a square crop to keep the selected demo crop from being stretched when it is resized.

What is a pixel, and what does resizing change?

A pixel is one small square of color or brightness in a digital image. Resizing samples or combines pixels to fit the requested width and height. It makes shapes comparable in size, but can stretch a very wide or tall crop because the code resizes directly to a square.

STEP 2 · MAKE TWO VIEWS

Keep one color copy and make one gray copy

We need two kinds of evidence. Color may help separate an apple from a neutral-colored stapler. Edge direction and shape can help distinguish a cup from toothpaste packaging. A grayscale image keeps brightness but removes hue and saturation; the color image is kept separately so that information is not lost for the color feature.

Why not feed color into every calculation?

Histogram of Oriented Gradients is designed to summarize brightness changes across neighboring pixels. It does not need color channels to find those changes. The separate HSV histogram deliberately summarizes color in a different way.

STEP 3 · NORMALIZE LOCAL CONTRAST

Apply CLAHE before calculating edges

CLAHE stands for Contrast-Limited Adaptive Histogram Equalization. In simple terms, it adjusts brightness contrast separately in small neighboring regions rather than applying one adjustment to the whole crop. This can make faint edges easier to see when lighting varies across an object. “Contrast-limited” means it caps the adjustment so a small dark region is not amplified without bound. This run uses OpenCV CLAHE with clipLimit 2.0 and an 8 by 8 tile grid.

What is contrast?

Contrast is the difference in brightness between neighboring parts of an image. A dark outline next to a bright background has strong contrast; two similar shades have weak contrast. HOG relies on these changes.

STEP 4 · HOG · SHAPE AND EDGE DESCRIPTION

HOG counts which way brightness edges point

Histogram of Oriented Gradients (HOG) is a method for summarizing edge directions. Imagine looking at a small patch of an object. Where brightness changes quickly, there is an edge. HOG measures the direction of those changes—horizontal, diagonal, vertical—and records how strong each direction is. It repeats this for many small regions and joins the measurements into one long list.

This is not a list of object parts and it does not understand the word “cup.” It is a numeric pattern of local edges. A model later learns that certain patterns often occurred in crops labelled cup, cans, or another class.

The selected direction represents diagonal edges. HOG assigns edge strength to direction bins across each small cell.

How do 9 directions, 8-pixel cells, and 2 × 2-cell blocks create 8,100 numbers?

The resized image is 128 pixels wide and high. Dividing it into 8-pixel cells gives a 16 by 16 grid. Each HOG block covers 2 by 2 neighboring cells; sliding that block one cell at a time gives 15 by 15 block locations. For each of the four cells in a block, HOG records nine direction-bin values. The resulting size is 15 × 15 × 2 × 2 × 9 = 8,100 values. The blocks overlap, which lets the description capture edges in nearby context.

L2-Hys is the normalization used for each block. It rescales the values so a block's description is less sensitive to overall brightness or contrast, then limits unusually large values before normalizing again.

STEP 5 · HSV · COLOR DESCRIPTION

A color histogram counts color ranges

We convert the color image from BGR (the order OpenCV reads) to HSV: Hue is the kind of color, Saturation is how vivid or grayish it is, and Value is brightness. We split each of those three channels into eight ranges. One count for every combination gives 8 × 8 × 8 = 512 bins, then the histogram is L2-normalized: the vector is scaled by its overall length so its magnitude is comparable across crops. OpenCV L2 normalization divides the vector by the square root of the sum of its squared bin values.

A histogram records how much of each color range appears, but not where in the image it appears. The HOG half contributes local edge layout; the HSV half contributes an overall color summary.

Why HSV rather than RGB?

In RGB, brightness and color are mixed across red, green, and blue values. HSV gives the histogram a hue axis and a separate brightness axis. This is a useful representation choice, though it does not make the features immune to lighting changes.

04

BASELINE AND MODEL CHOICES

Three ways to draw class boundaries

The project compares three model families because they learn different kinds of rules from visual feature values.

Logistic Regression is the linear baseline. The RBF Support Vector Machine can represent curved boundaries, and a Random Forest combines many decision trees. In pipeline v1, each model family learned from the combined 8,612-value vector. In v2, each family has one classifier for HOG and a second for color; their probabilities are blended after prediction.

A baseline is a reasonable first method used as a reference for later changes. We held the model families constant across versions so the comparison could focus on the revised image preparation, feature handling, and tuning. V2 searched model settings and the HOG/color fusion weight using five-fold validation inside the training pool.

A MODEL LEARNS A RULE

During training, an algorithm sees numeric feature rows paired with known labels. It adjusts internal values so its predictions better match those labels. After training, new feature values can be assigned to the class whose learned rule fits best.

The model family stays the same in v2; the change is that shape and color are learned in separate streams before their scores are combined.

01 · LINEAR

Logistic Regression

It combines feature values with learned weights and calculates a score for each class. The largest score determines the prediction. Despite “regression” in its name, this version is used for classification.

What does “linear” mean here?

For each class, the model adds weighted feature values. The boundary between classes is a flat dividing surface in the high-dimensional feature space. “Flat” does not mean the crop looks like a line; it describes the mathematical decision rule.

02 · KERNEL

Support Vector Machine · RBF

An SVM searches for a boundary that separates classes with a wide margin. The RBF kernel lets that boundary bend based on similarity between examples, so it can capture more complex patterns than a flat boundary.

What is a kernel?

A kernel computes how similar two feature vectors are, without requiring the model to explicitly construct a new giant feature space. RBF means radial basis function: examples close together in feature space have more influence on each other than far-apart examples.

03 · ENSEMBLE

Random Forest

A forest trains many decision trees. Each tree asks a sequence of feature-value questions and reaches a class at a leaf. The forest combines the trees' outputs. It provides a useful contrast to the smooth boundary of an RBF SVM.

What is a decision tree?

A tree is a chain of if/then splits, such as “is this feature above a threshold?” Each split narrows the possible classes until a leaf supplies a result. A random forest averages many trees rather than relying on one chain.

V2 PARAMETER SEARCH

What did the two-stream tuning select?

A hyperparameter is a setting chosen before fitting that controls a model. V2 tried candidate model settings together with three fusion weights: α=0.3, 0.5, or 0.7. Five-fold cross-validation compared the fused predictions using only the training pool. The HOG and color scalers are fitted separately inside each fold. The selected α is the share assigned to HOG; the remaining share goes to color.

HOW V2 CLASS SCORES ARE MADE

Two probability lists are calibrated, then blended

For Logistic Regression and SVM, v2 uses three-fold sigmoid calibration inside each HOG and color classifier. Calibration maps model scores to probability-like class scores, making the two streams easier to blend. Random Forest supplies tree-vote probabilities directly. The final five class scores are the weighted average of the HOG and color scores. Calibration makes scores usable for this combination, but does not guarantee perfect real-world probability accuracy.

WHY THIS MATTERS

A threshold depends on the score

The rejection rule compares the top fused class score with a chosen threshold. A threshold is a policy for accepting or flagging a prediction; it does not change the model’s probability scores. A score is not a promise that a prediction is correct, and the same threshold can yield different coverage for each model.

05

EVALUATION DESIGN

Keep the final exam unseen

We set aside the final test portion first, tune only inside the remaining training pool, and report the test result after the choices are fixed.

This is a three-level process: (1) the training pool fits candidate models, (2) five-fold cross-validation estimates how candidate settings perform and selects hyperparameters, and (3) the separate held-out test set checks the selected model at the end. The test set contains 20% of the crops (838 examples); it was not used to choose settings and is evaluated once per model in the final evaluation script. That separation makes the reported test score a more independent estimate of performance on similar unseen crops.

The split uses test_size=0.2, stratification, and random_state=42. The fixed random state makes the same rows reproducible each run; stratification keeps each class in roughly the same proportion in the training pool and test set. The remaining 80% (3,350 crops) is the training pool. In five-fold stratified cross-validation, it is divided into five parts: each round fits on four parts and validates on the fifth, rotating until each part has served as validation. Grid search compares the candidate hyperparameters using these five validation results. After selection, the chosen model is refit on all 3,350 training-pool crops, then evaluated on the untouched 838-crop test set.

WHAT CROSS-VALIDATION MEANS

Five validation rounds, one training pool

A validation fold is a temporary set of examples used to compare settings while the model is being developed. It is different from the final test set: the CV scores help choose hyperparameters, while the test score is reserved for the final report. “Stratified” means each fold keeps approximately the same mix of the five labels, so a round is not accidentally missing a class.

IMPLEMENTATION CAVEAT

V2 keeps fold scaling separate

The original v1 tuning script fit StandardScaler on the full training pool before making CV folds, allowing each fold’s validation images to influence its scaling averages. In v2, the tuning code fits each stream’s scaler using only that round’s four training folds, then applies it to that round’s validation fold. The final test set remains separate in both versions. The split is still crop-level, so results estimate performance on similar crops from this dataset rather than guaranteeing performance on entirely new scenes or environments.

DEBUGGING STORY · FROM V1 TO V2

What we learned after the first pipeline

The first model gave us a working baseline. Looking at how it behaved led us to revise both image preparation and how shape and color evidence are combined.

V1: one long feature list. Each crop was directly resized to 128 × 128, even when its original bounding box was rectangular. That can squash or widen an object. HOG produced 8,100 edge-orientation values and the HSV histogram produced 512 color values; these were concatenated into one 8,612-value vector. StandardScaler normalized each feature column, but normalization did not make the two feature groups equally influential: many more HOG dimensions could contribute to distance calculations.

What we noticed. Small differences in how an uploaded crop was resized could shift edge locations and change HOG values. In the original held-out results, the Random Forest missed 30 of 127 staplers (23.62% false-negative rate), while the other models missed 10 and 14. These observations motivated an investigation; they do not by themselves prove that either issue caused every error.

V2 CHANGE 1 · PRESERVE SHAPE

Letterbox before resizing

V2 adds replicated edge pixels to the shorter side until the crop is square, then resizes the square uniformly to 128 × 128. “Letterbox” means filling the unused space around an image so the whole object fits a fixed frame without stretching it. Replicating edge pixels avoids drawing a new, sharp, flat border that could look like an artificial edge to HOG.

V2 CHANGE 2 · KEEP STREAMS SEPARATE

Blend decisions, not raw columns

V2 trains one HOG classifier and one color-histogram classifier for each model family. Each stream has its own StandardScaler. A classifier’s probability scores are then combined: alpha × HOG probability + (1 − alpha) × color probability. Cross-validation tunes alpha and the model settings together. All three selected alphas were 0.5, so each stream contributes half of the combined score.

LIMITS AND NEXT QUESTIONS

What these results can—and cannot—support

Good results on pre-cropped examples support a narrow claim: these features can distinguish these five classes in this dataset.

They do not establish that a robot can find the objects in a new room, handle occlusion, or grasp safely. The experiment removes detection from the question by using reference bounding boxes; the live demo asks the visitor to make the crop for the same reason.

A SMALL CHANGE TO DEFEND

If we raised the confidence threshold, more low-score cases would be sent for review. Coverage would fall, while accuracy among the accepted cases may rise. The exact trade-off must be read from the saved held-out threshold data; it cannot be inferred from one test accuracy.

DATA DISTRIBUTION

Five selected classes

These class counts are intentionally close, between 636 and 916. A real sorting bin might have many more of some objects than others. This experiment does not study that broader imbalance.

FEATURE LIMIT

Edges are not object understanding

HOG can encode boundaries from text or logos on a package. It does not know whether an edge came from a can's silhouette or a printed word. A convolutional neural network could learn richer visual cues, but was outside this classical-ML scope.

DECISION LIMIT

Confidence is not physical safety

The demo's “GRASP” badge means only that the top identity score clears a user-selected threshold. It does not estimate pose, force, collision risk, or whether a grasp will succeed.
